# ACB email API v1

All RPCs return JSON. Dates are ISO timestamptz strings; UUIDs strings. Unknown worker operations fail 22023. `bank_email_worker_v1(p_operation text,p_payload jsonb)` is service_role-only. Never send actor/org in worker money requests: DB derives actor from the connection, rechecks current permissions and restores request JWT claims after delegated V5.

## UI

- `bank_email_setup_v1(p_organization_id uuid,p_bank_account text,p_account_id uuid)` → Connection. Immutable bank-account mapping is globally unique, including disconnected connections. Same owner/org/account setup returns existing connection.
- `bank_email_set_enabled_v1(p_connection_id uuid,p_enabled boolean)` → Connection. Enabling establishes a fresh autoEnabledAt cutoff; requires CONNECTED.
- `bank_email_disconnect_v1(p_connection_id uuid)` → Connection. Immediately disables posting; revocation queued. Stored owner may disconnect after losing business permissions so OAuth access can always be revoked.
- `bank_email_review_v1(p_transaction_id uuid,p_invoice_number text,p_ignore boolean default false,p_expected_invoice_id uuid default null,p_expected_amount numeric default null)` → TransactionReceipt. Post requires both expected fields and checks them against the source amount and selected invoice ID before V5; changed selection raises PT409/HTTP 409 (including POSTED replay with different expected invoice/amount). Ignore may omit expected fields and is persistent. Manual review still requires verified CREDIT/VND, exact account/amount and current authorization. No old three-argument overload remains.
- `bank_email_my_connections_v1()` → `{connections:[{id,email:string|null,status,organizationId}]}`. Authenticated stored owner only, even after business permission/membership loss; minimal metadata for revoke controls in the account profile. Never includes bank account/cashbook/transactions/credentials.
- `bank_email_transaction_v1(p_transaction_id uuid)` → Transaction. Exact source refetch after an uncertain network response; requires owner and current business/invoice access. Missing or denied ID raises 42501.
- `bank_email_list_v1(p_organization_id uuid,p_before timestamptz default null,p_limit integer default 30)` → `{connections: Connection[],transactions: Transaction[],hasMore:boolean}`. Descending createdAt; rows share no timestamp (DB allocates a globally monotonic cursor under a short advisory transaction lock). Caller must own connections and still have configuration/receiving rights.
- `bank_email_oauth_begin_v1(p_connection_id uuid,p_state_hash text,p_verifier_encrypted text)` called **using the user's JWT**, never service credentials → `{id:string,status:"AUTHORIZING"}`. Worker supplies SHA256 state hash + opaque encrypted PKCE verifier. Expires after 10 minutes; one-use callback. Existing credentials require disconnect and completed worker revocation before reconnect; token replacement never drops an old credential.

Connection = `{id,organizationId,bankAccount,accountId,enabled:boolean,autoEnabledAt:string|null,status:"DISCONNECTED"|"AUTHORIZING"|"CONNECTED"|"RECONNECT_REQUIRED",email:string|null,lastSyncedAt:string|null,lastError:string|null,createdAt:string}`.

Transaction = `{id,connectionId,messageId,internalDate:string,verified:boolean,account:string|null,amount:number|null,balance:number|null,currency:string|null,direction:string|null,occurredAt:string|null,bankReference:string|null,description:string|null,status:"PENDING"|"POSTED"|"IGNORED",reason:string|null,invoiceId:string|null,receipt:object|null,createdAt:string}`. TransactionReceipt = `{id,status,reason:string|null,invoiceId:string|null,receipt:object|null}`. No raw email, tokens, PKCE verifier or worker leases in UI results.

## Worker operations

- `oauth_consume`: `{stateHash}` → `{connectionId,encryptedVerifier}`; atomically consumes fresh state once. Expired/replayed state rejects.
- `oauth_complete`: `{stateHash,email,encryptedRefreshToken,historyId,watchExpiresAt}` → `{id,status:"CONNECTED"}`. Requires consumed, uncompleted, unexpired state; locks connection; complete once. Email lowercase, historyId decimal string; ciphertext opaque max 16 KiB. Starts with a **null durable cursor** so the first job performs a full ACB scan; watch historyId is validated but does not skip preexisting mail. Auto stays disabled until user enables. One Gmail email is unique across credentials globally, including pending revocation. On email collision discard the callback token without revoking it: Google revocation may revoke the existing shared grant. The existing connection is preserved.
- `enqueue`: `{email}` → `{queued:number}`. Called after independently authenticating Pub/Sub JWT. Coalesces durable job; never modifies cursor. Unknown email returns zero.
- `claim`: `{}` → `{jobs: Job[]}` at most 10 due jobs, each leased 120 seconds via SKIP LOCKED; schedules connected catchup every 5 minutes. Job = `{connectionId,leaseToken,encryptedRefreshToken,email,historyId:string|null,watchExpiresAt:string|null,scanPageToken:string|null,scanHistoryId:string|null,historyPageToken:string|null,historyStartId:string|null,disconnect:boolean}`. Expired leases can be reclaimed. Before returning CONNECTED credentials DB rechecks the stored owner's current authority. Revocation marks RECONNECT_REQUIRED/PERMISSION_REVOKED, disables auto and returns no token/job. Disconnect jobs still carry token solely for Google token revocation, never Gmail.stop. All claims lock connection before job, matching mutation lock order.
- `checkpoint`: `{connectionId,leaseToken,historyId,watchExpiresAt?}` → `{ok:true}`. Requires live lease + CONNECTED, advances cursor monotonically; worker MUST call only after persisting all fetched messages/pages. Watch renewal must not skip unprocessed history.
- `watch_metadata`: `{connectionId,leaseToken,watchExpiresAt}` → `{ok:true}`. Live lease + CONNECTED, only updates a finite future expiry. Safe when initial cursor is null or a paginated scan is unfinished.
- `scan_checkpoint`: `{connectionId,leaseToken,scanHistoryId,pageToken:string|null,complete:boolean}` → `{ok:true}`. Begin with a profile history snapshot before full scan; checkpoint next pageToken only after ingesting the entire page. Snapshot is fixed until complete. Partial scans clear obsolete history pagination state and survive leases. Completing advances cursor to the snapshot, clears scan state; subsequent history catches messages arriving during the scan.
- `history_checkpoint`: `{connectionId,leaseToken,startHistoryId,pageToken:string|null,complete:boolean,finalHistoryId?:string}` → `{ok:true}`. Start ID must equal durable cursor when beginning. Partial pages persist after ingest. Complete requires finalHistoryId ≥ startHistoryId and advances cursor only after all pages. Partial scan/history makes `finish` reschedule immediately; next claim resumes from saved page.
- `page_progress`: `{connectionId,leaseToken,mode:"scan"|"history",pageToken:string|null,messageId}` → `{ok:true}`. Live lease, matching active mode and current page token required. Persist after each successfully ingested or deliberately skipped ordinary message, including within a page that exceeds one lease budget. Idempotent by messageId, stored in a private child table without a total page-count cap. Changing page, completing, or switching mode clears progress; checkpointing the same page preserves it.
- `page_pending`: `{connectionId,leaseToken,mode:"scan"|"history",pageToken:string|null,messageIds:string[]}` → `{pendingMessageIds:string[]}`. At most 500 message IDs per call. Same current page/mode/lease guard; returns input IDs not yet processed in input order. Worker checks each chunk before processing. Claim never carries processed IDs, keeping its response bounded. A single Gmail history record can contain more than 1,000 message additions.
- `ingest`: `{connectionId,leaseToken,messageId,internalDate,verified,parsed:{account,amount,balance,currency,direction,occurredAt,bankReference,description}|null,parseError:string|null}` → TransactionReceipt. Dates ISO strings, integer VND amount > 0 ≤ 1e15, balance integer ≥ 0 ≤ 1e15, account digits 6–30, ref ≤ 128, description ≤ 4000. Invalid/unverified parsed messages remain pending; no raw content. Connection/message dedup plus global bank-account/reference claim prevents double posting across messages/invoices/actors. Live lease required.

Pending canonical writer rejections remain PENDING/WRITER_REJECTED on message/source replay, with a single notification. Current authority is checked before this conversion; a revoked actor or unauthorized posted replay raises 42501 instead of returning a receipt. Successful retry updates the existing notification to posted.
- `finish`: `{connectionId,leaseToken}` → `{ok:true}`. Releases lease; keeps a concurrent enqueue due, otherwise next catchup in 5 minutes. For disconnect job, deletes token and job after successful revocation.
- `fail`: `{connectionId,leaseToken,errorCode,reconnect:boolean}` → `{ok:true}`. Error code sanitized to `[A-Z0-9_]{1,80}`, no exception/token contents. Retry in 1 minute; reconnect marks RECONNECT_REQUIRED and disables auto. Does not advance cursor.

All connection-specific lease operations reject stale/wrong leases. Worker should stop a job on 42501/40001; unexpected errors remain retryable through lease expiry. Long Gmail work must finish inside 120 seconds or fail safely and retry; no heartbeat extension in v1.
